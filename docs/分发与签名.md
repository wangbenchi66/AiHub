# AiHub 分发与签名（免费方案）

> 适用版本：v1.0 · 2026-10-23
> 前提：**没有购买 Windows 代码签名证书，也没有 Apple Developer Program 账号。**
> 结论：v1 用「未签名 + 明确引导」分发；不发布校验文件，不把"关闭系统安全"作为安装步骤；开源后再申请免费 OSS 签名。

---

## 0. 先说结论

| 平台 | v1 方案 | 用户看到什么 | 成本 |
|---|---|---|---|
| Windows | 未签名 NSIS / 便携版 | SmartScreen「Windows 已保护你的电脑」→ 更多信息 → 仍要运行 | 0 |
| macOS | ad-hoc 签名 + 未公证 DMG | Gatekeeper「无法验证开发者」→ 系统设置里允许打开 | 0 |
| 代码签名（可选增强） | 开源后申请 SignPath Foundation / Certum OSS | 发布者显示为证书主体，SmartScreen 逐步建立信任 | 0（需审核） |
| Apple 公证 | v1 不做；要免警告只能加入 Apple Developer Program | 无警告 | $99/年 |

**不推荐**：让用户执行 `spctl --master-disable` 全局关闭 Gatekeeper；这会降低整机安全性，也不专业。

## 1. Windows：未签名 + SmartScreen 引导

### 1.1 为什么没有免费"立即可用"的公共证书

Windows 的 SmartScreen 信任来自证书链与发布者声誉。自签名证书不被系统信任，仍然会弹警告；免费公共证书只对**开源项目**开放，且需要审核，不能即拿即用。

### 1.2 v1 的分发方式

- 产物：`AiHub-Setup-<version>.exe`、`AiHub-<version>-x64.exe`（便携版）
- 不发布 `SHA256SUMS.txt`；发布页只放安装包和说明。
- 安装包内不放"关闭 Defender/SmartScreen"的脚本。
- README / 下载页写清楚：

```text
AiHub 暂未购买代码签名证书，Windows 首次运行可能提示
"Windows 已保护你的电脑"。

请：
1. 点击"更多信息"
2. 点击"仍要运行"

如果下载的是 zip，右键 → 属性 → 勾选"解除锁定"后再解压。
```

### 1.3 免费/低成本签名选项（按推荐顺序）

| 方案 | 是否免费 | 适用 | 说明 |
|---|---|---|---|
| **SignPath Foundation** | ✅ 开源项目免费 | 公开仓库 | 提供代码签名证书，私钥在 HSM；集成 GitHub Actions；需申请审核 |
| **Certum Open Source Code Signing** | ✅ 开源项目（需审核） | 公开仓库 | 需身份/项目审核；具体资格以 Certum 当期政策为准 |
| 自签名证书 | ✅ 免费 | 仅内网/自用 | 其他电脑不信任，SmartScreen 仍警告；**不用于公开分发** |
| Microsoft Store | 可能有免费/减免政策 | 上架商店 | 由商店签名分发；账号费用与地区政策会变，需另行确认 |
| Azure Trusted Signing | ❌ $9.99/月起 | 商业 | 便宜但不是免费；需要 Azure 订阅与身份验证 |

> SignPath 官方原话：For OSS projects, our services are free of charge。
> 参考：[SignPath Foundation](https://signpath.org/)、[electron-builder Code Signing](https://www.electron.build/code-signing)

### 1.4 如果以后拿到证书

electron-builder 已经预留配置，只需在 CI 注入环境变量，不改代码：

```yaml
win:
  signingHashAlgorithms: [sha256]
  certificateFile: ${env:WIN_CSC_LINK}
  certificatePassword: ${env:WIN_CSC_KEY_PASSWORD}
```

## 2. macOS：ad-hoc 签名 + Gatekeeper 引导

### 2.1 为什么没有免费公证

Apple 的 notarization 只对 **Apple Developer Program** 成员开放，个人账号 $99/年。没有会员资格就无法获得可被 Gatekeeper 直接信任的签名/公证链。 nonprofit / 教育机构可以申请费用减免，但个人开发者不适用。

参考：
- [Apple Developer Program](https://developer.apple.com/programs/)
- [Notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
- [macOS Sequoia runtime protection 变化](https://developer.apple.com/news/?id=saqachfa)

### 2.2 v1 的分发方式

- 构建：`electron-builder --mac dmg zip`，`identity: null`（不签名）或在 `afterSign` 执行 ad-hoc：
  ```bash
  codesign --force --deep --sign - "AiHub.app"
  ```
- ad-hoc 签名是免费的，能避免部分"应用已损坏"问题，但**不能**让 Gatekeeper 认为开发者可信。
- DMG 内附 `首次打开说明.txt`，不发布校验文件。

### 2.3 用户首次打开（按 macOS 版本）

**macOS 15 Sequoia 及以上**（Apple 移除了右键 Open 的快捷方式）：

1. 打开 DMG，把 AiHub 拖进"应用程序"。
2. 双击 AiHub，出现"无法验证开发者"。
3. 打开 **系统设置 → 隐私与安全性**，向下滚动到"安全性"。
4. 点击 **仍要打开**，输入密码确认。
5. 再次双击 AiHub。

**macOS 14 及更早**：

1. 在"应用程序"里 **右键 → 打开**。
2. 在弹窗中再次点 **打开**。

**终端方式（可选，需用户自己确认风险）**：

```bash
xattr -dr com.apple.quarantine /Applications/AiHub.app
```

> 不要把这条命令写成"安装必需步骤"，也不要建议全局关闭 Gatekeeper。把它放在"高级排查"里，并说明它移除了系统的下载隔离标记。

### 2.4 无警告的替代路径

- **自行构建**：从源码 `npm run build:mac`，本机构建产物不带 quarantine，不会触发下载警告（适合开发者）。
- **Homebrew Cask**：仍然受 Gatekeeper 约束，不能绕过公证。
- **Mac App Store**：需要开发者账号，且 Electron 上架限制多，不作为 v1 方案。

## 3. 完整性说明

v1 不发布 `SHA256SUMS.txt`，Release 只包含安装包和说明文件。

- GitHub Releases 使用**签名 tag**，构建由 GitHub Actions 产出，减少"本地打包混入东西"的疑虑。
- 如需自行核对，可在本机执行 `Get-FileHash <文件> -Algorithm SHA256`，但这不是安装必需步骤。

## 4. CI 与发布流程（v1）

工作流：`.github/workflows/release.yml`，只在推送 `v*` tag 时触发；tag 必须与 `package.json` 的 `version` 一致（`v0.1.3` → `0.1.3`）。

```text
push tag v0.1.3
  ├─ validate:        tag 与 package.json 版本一致
  ├─ windows-latest:  npm ci → typecheck → build → electron-builder --win（未签名）
  ├─ macos-latest:    npm ci → typecheck → build → electron-builder --mac（ad-hoc）
  └─ release job:     下载两平台产物 → GitHub Release
```

发布内容：

- `AiHub-Setup-<version>.exe`（NSIS）
- `AiHub-<version>-x64.exe`（便携版）
- `AiHub-<version>-x64.dmg` / `-arm64.dmg`
- `AiHub-<version>-x64.zip` / `-arm64.zip`

- Windows 和 macOS 的包不能互相交叉构建；必须用双平台 runner。
- 不在 CI 里保存任何证书；v1 没有证书。
- 以后申请到 SignPath/Certum：只在 CI 中加 secrets，构建脚本不变。
- 版本号带 `-`（如 `v0.1.0-beta.1`）时自动标记为 prerelease。

参考工作流见 [技术方案 §13](../技术方案.md#13-打包与分发)。

## 5. 给用户的说明模板

放在下载页、README、DMG 内：

```text
关于系统安全提示

AiHub 是独立开源工具，暂未购买商业代码签名证书，因此：
- Windows 可能提示"Windows 已保护你的电脑"
- macOS 可能提示"无法验证开发者"

这不是病毒提示，而是系统对"未签名应用"的统一提醒。
- Windows：更多信息 → 仍要运行
- macOS 15+：系统设置 → 隐私与安全性 → 仍要打开
- macOS 14-：右键应用 → 打开

如果你不希望出现该提示，可以从源码自行构建，或等待项目获得
SignPath / Certum 的开源签名，以及 Apple Developer 公证。
```

## 6. v1 产物结构

```text
release/AiHub-Setup-<version>.exe   NotSigned
release/AiHub-<version>-x64.exe     NotSigned
release/
```

- `Get-AuthenticodeSignature` 结果为 `NotSigned`，符合预期。
- macOS 构建通过 `scripts/after-pack-mac.cjs` 做 ad-hoc 签名；未在 macOS 实机验证，首次打开仍需按 §2.3 放行。
- 安装包未签名不代表"不可用"：系统提示是平台对未知发布者的统一策略，不影响功能。
